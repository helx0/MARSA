# MARSA | مرسى — Aden Seafood Marketplace

**Source delivery status:** This repository contains Flutter application source, Android platform scaffolding, Supabase migrations, RLS policies, transaction RPCs, a scheduled function, automated test source and engineering documentation. **It has NOT been compiled, run on an Android device, or connected to a live Supabase project in the delivery sandbox.** The sandbox has Java but no Flutter SDK, Dart SDK, Android SDK, network access to package hosts, Supabase credentials or running PostgreSQL. Do not mistake source-level checks for a verified APK. See `TESTING.md` for the exact verification gap.

## What this app actually implements in source

- Aden-only seafood listings, search, category/area/mode filters, paging, product details and an offline-labelled **read-only** recently viewed cache.
- Email/password signup/signin, email reset/recovery deep-link handling, Arabic-first material UI with partial English translation, profile, private contact field.
- Seller application and administrative approval, listing creation, image upload, drafts, moderation, editing, stock and direct price controls.
- Direct purchase checkout with payment by cash on handover or manual external agreement (no payment gateway), server-side stock row locks and idempotency keys.
- Timed auctions, server-clock-based countdown approximation, bid transaction locking, anonymized bid-amount activity, scheduled/on-demand finalization, 48-hour winner deadline (default policy), no automatic runner-up award.
- Seller/buyer order state transitions, order history, private messaging, message block/report, favorites, completed-order review, notifications.
- Role-protected admin UI for approvals, moderation, reports/disputes, references, account suspension and audit events. **Backend roles are checked by SQL**.

## Supabase setup

1. Create Supabase project and save its **Project URL** plus **publishable / anon public key**. Never copy the service-role key into Flutter, version control or `--dart-define`.
2. Turn on email/password authentication under Authentication → Providers. Decide whether to require email verification. Add `marsa://login-callback/` to Authentication → URL Configuration → Redirect URLs, then configure an SMTP sender before real user launch.
3. Apply migrations **in filename order**: `supabase/migrations/202611190001_foundation.sql`, `202611190002_operations.sql`, `202611190003_guards.sql`, `202611190004_security_hardening.sql`, `202611190005_stock_lifecycle.sql`, and `202611190006_media_guard.sql`, `202611190007_search.sql`, `202611190008_direct_expiry.sql`, `202611190009_private_rls.sql`, and `202611190010_suspended_seller_visibility.sql`. With Supabase CLI linked to your development project, use `supabase db push`. Review SQL before running against any non-development environment.
4. Apply `supabase/seed/001_aden.sql` in the SQL Editor **once** (or `psql` against your dev connection). It creates Aden-area and seafood category reference records, **not** fake sellers/listings.
5. The migrations configure the public `listing-images` and private `seller-private` Storage buckets, restrict MIME types and set 5 MB upload limits. Verify bucket policies and uploads on the staging project.
6. Create your own admin account by normal sign-up and verifying email. Assign administrator status using *trusted SQL run in Supabase SQL Editor*, **not via a client**:

   ```sql
   insert into mars_private.admin_users(user_id)
   values ('REPLACE-WITH-REAL-AUTH-USERS-UUID');
   ```

7. Deploy the scheduled function: `supabase functions deploy finalize-auctions --no-verify-jwt`, then `supabase secrets set CRON_SECRET=<long-random-secret>`. Schedule an **authenticated POST** to the function (e.g., every minute) including header `x-cron-secret: <same-secret>` using a trusted server-side scheduler. The function invokes the `finalize_due_auctions` RPC with the service-role key *server-side only*. Without the scheduler, expired auctions can be finalized on-demand by authenticated app users, but unattended deadlines are not guaranteed.
8. Review RLS tests and upload security before enrolling real users.

## Run / build

**Never check the public key into a publicly shared build if your own security policy prohibits it.** The anon key is designed to be public; server-side RLS must remain enabled and tested.

```bash
flutter doctor -v
flutter pub get
# Run on Android emulator or device:
flutter run --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co --dart-define=SUPABASE_ANON_KEY=YOUR_PUBLIC_KEY
flutter analyze
flutter test
flutter build apk --debug --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co --dart-define=SUPABASE_ANON_KEY=YOUR_PUBLIC_KEY
```

If you omit both `--dart-define` settings the application intentionally displays a backend-configuration error instead of claiming real transactions succeeded. Do not ship a release APK with the `debug` signing configuration; set a secure signing key in your local Android build before publishing.

## Troubleshooting

- `flutter: command not found` → install Flutter and add its `bin` directory to PATH.
- `flutter.sdk not found` → run `flutter pub get` / Android Studio Flutter setup; verify generated `android/local.properties`.
- Gradle download fails → allow HTTPS to `services.gradle.org`, Gradle Plugin Portal, Google Maven and Maven Central. Gradle wrapper can be replaced with standard wrapper via locally installed Gradle.
- `relation ... does not exist` → migrations and seed were not applied, or the app points to a different Supabase project.
- `permission denied` / 42501 → review seller approval, account status, and RLS policies; do **not** bypass them by shipping a service key.
- No visible listings → listings begin as `DRAFT` and require submission then moderator approval to become ACTIVE. No fabricated listings are shipped.
- Password reset link opens browser only → configure the redirect URL and Android deep link, then test on-device with your Supabase email template.
- APK not building → run commands above with your actual installed Flutter/Android SDK; capture analyzer output and build logs, since this environment could not execute those commands.
